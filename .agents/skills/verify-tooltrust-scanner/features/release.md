# Release verification

Before tagging, run `verify.py drive --run "$TT_VERIFY_RUN" --feature release` after launch. Node.js 22+, npm and Go are required. It checks VERSION, npm package version/binary pin and server.json, packs the actual npm tarball, enforces its file allowlist, installs it with scripts disabled into owned scratch state, and tests the packaged wrapper with the release-version binary. Assert initialization/tool listing, empty scan errors, OSV 503 errors, cache reuse and a failing exit for an invalid cached executable. The preflight seeds a freshly built binary and does not claim a real release download.

After GitHub release assets exist, run `node scripts/verify-npm-release.js --published --run /absolute/fresh/owned/path`. This tests a cold download of the exact pinned release, checks both MCP/CLI SHA256 against platform checksum assets, verifies binary versions and CLI empty-input failure, then repeats wrapper/cache/error assertions. Release CI runs it on Linux, macOS and Windows. It needs GitHub network access. Evidence stays under the owned run's evidence directory; caches/install files are isolated by TOOLTRUST_CACHE_DIR and npm config/cache flags.

Only publish npm after the exact release asset tests pass. Verify npm registry metadata/tarball after publication. Update Homebrew version/checksum only once the tag archive exists, and validate the formula PR. Release notes must explain changed exit semantics. Registry publication to the MCP catalog, real Claude installation and signing/provenance guarantees are NOT established by these checks.
